# 3. 방법 (한글 검토용 — 영문판 03_method_04_setup.md v3와 1:1 대응)

## 3.1 개요

우리 파이프라인은 diffusion inpainting 모델로 **배경만** 재생성하고 주석된
객체는 기하학적으로 보호한 합성 이미지를 학습 데이터에 추가한다(그림 1).
합성 이미지 *B*장의 고정 예산과 고정 대상 클래스 수 *K*가 주어지면 *배분
계획*이 클래스별 이미지 할당량을 정한다. 대상 클래스가 등장하는 학습
이미지를 소스로 뽑아 **모든** 주석 박스 밖을 inpainting하고, 정량 기준의
규칙 기반 품질 검증(3.4절)을 통과한 이미지만 **학습 split에만** 삽입한다.
이 설계는 단 하나의 질문을 고립시킨다: 생성기·프롬프트·품질 검증·예산·
클래스 수를 고정했을 때, 예산을 받을 클래스를 고르는 규칙인 **배분 신호**가
성능 이득의 위치를 바꾸는가?

## 3.2 배분 설계: 클래스 집합 × 집합 내 가중

두 배분 신호와 두 집합 내 가중을 조합해 증강 arm의 2×2 요인 설계를 만든다:

- **Tail 집합 (빈도 신호).** 학습 인스턴스 수 하위 30% 클래스 — 통상적
  long-tail 처방.
- **Weak 집합 (난이도 신호).** `basic_aug` baseline 검출기가 **검증 split**
  에서 측정해 학습 seed에 걸쳐 평균한 클래스별 average precision(AP) 하위
  *K*개. *K*는 tail 집합 크기와 같게 고정해 집합의 *정체*만 조작 변수로
  남긴다.
- **Uniform 가중**은 *B*를 *K*개 클래스에 균등 분할한다.
- **Weighted 배분**은 우선순위 점수에 비례해 *B*를 나눈다: tail 집합은
  희소성과 측정된 약점의 볼록 결합(희소성 쪽 가중 0.6), weak 집합은 측정된
  약점 단독.

할당량은 결정적 capped largest-remainder 할당기로 계산한다: 각 클래스가
먼저 최소 할당을 받고, 잔여분은 클래스별 상한 아래에서 가중치에 비례
배분되며, 소수 잔여는 나머지가 큰 순서(동률은 인덱스 순)로 1장씩 간다.
할당기는 모든 arm이 정확히 *K*개 클래스에 정확히 *B*장을 쓰도록 보장하므로
예산이 비교를 교란할 수 없다. 경험적으로 두 집합은 자연 시점 벤치마크에서
서로소이고 위성 시점 벤치마크에서는 미미하게만 겹치며(4.1절) — 빈도와 측정 난이도가 실제로 다른
클래스를 고른다(5.1절) — 이것이 요인 설계를 유의미하게 만든다.

## 3.3 배경 inpainting 생성

합성 이미지는 Stable Diffusion inpainting(`runwayml/stable-diffusion-
inpainting`, 16비트 부동소수점, denoising 20 steps, guidance scale 7.5,
strength 0.85)으로 512×512 작업 해상도에서 생성한 뒤 원본 해상도로
되돌린다. 소스 이미지마다 모든 주석 박스를 10% 패딩과 경계 blur 밴드로
**보호**하는 마스크를 만들어 diffusion이 배경만 바꿀 수 있게 한다. 장면
프롬프트는 데이터셋별이고(MAD: 자연 시점 항공 5종, MAR20: top-down 비행장
5종) negative prompt도 데이터셋별이며, 무엇보다 새 항공기의 생성을
억제한다. 생성 후 보호 영역은 소스 픽셀로 되붙여 객체 외형과 라벨이
구성상 정확하도록 만들고, 소스 라벨은 그대로 복사한다. 생성은 계획이
주어지면 완전히 결정적이다 — 각 출력은 소스 이미지, 프롬프트 로테이션,
파생된 이미지별 seed의 함수이므로 바이트 동일 재생성과 실험 간 안전한
재사용이 가능하다.

## 3.4 규칙 기반 품질 검증과 예산 재보충

소스 이미지는 먼저 inpainting이 의미 있을 만큼의 편집 가능 배경을 제공해야
하며(보호 영역이 프레임의 95% 이하), 이 사전 검사에 실패한 소스는 생성
전에 제외된다. 생성된 각 이미지는 두 정량 검사를 통과해야 한다: (i) 배경이
실질적으로 변했는가(박스 밖 평균 절대 픽셀 차 ≥ 10 gray level), (ii) 보호된
내부가 압축 노이즈 허용치 이상 변하지 않았는가(≤ 5 gray level). 실패한
생성은 재시도하고, 그래도 실패하면 제한된 시도 예산 안에서 다른 소스로
대체해 클래스 할당량을 채우므로 모든 arm이 같은 *실현* 예산에 도달한다.
전체 시도의 절반 이상이 실패하면 생성기 오작동으로 간주하고 실행을
중단한다. 추가 감사로 — 필터가 아니라 강건성 점검으로 보고 — 검출기 기반
스캔이 diffusion이 배경에 그려 넣는 **환각** 객체를 세고, object-level
gate 변형이 해당 이미지를 전부 제거한 채 arm을 재학습한다(5.4절).

## 3.5 학습 arm과 baseline

모든 arm은 검출기·스케줄·Ultralytics 학습 프레임워크의 기본 광학/기하
증강을 공유하며 학습 데이터만 다르다. `real_only`는 프레임워크 증강을 끈
참조 하한선이고, `basic_aug`가 모든 이득의 기준이 되는 주 baseline이다.
Repeat-factor sampling(RFS)은 무비용 재표집 baseline이다: f(c)를 클래스
c를 포함하는 학습 이미지의 비율이라 할 때, 각 이미지 I는 이미지에 등장하는
클래스들에 대한 최댓값 r(I) = max r(c)에 따라 복제되며, r(c) = max(1,
√(t/f(c))), t = 0.1이고 데이터셋 수준에서 물질화된다. 4개 inpainting arm은
각자의 *B*장 pool을 학습 split에 더한다. 검증·테스트 split은 결코 손대지
않는다.

## 3.6 통계 프로토콜

계획과 평가를 분리한다. 계획을 만드는 모든 측정(weak 집합 선택, 우선순위
점수)은 검증 split만 쓰고, 테스트 split은 최종 보고 전용이며, 테스트 지표
관찰 후 계획이나 하이퍼파라미터를 고치지 않았다. 전체 요인 셀에서는 5개
contrast를 테스트 split 지표가 존재하기 전에 내용 해시·타임스탬프와 함께
동결했다: (1) tail scope에서 tail arm 대 baseline, (2) weak scope에서 weak arm 대
baseline, (3) set×scope 상호작용, (4–5) 각 집합 내 weighted 대
uniform. contrast는 seed별 macro AP(scope 내 클래스들의 클래스별 AP 비가중
평균)에 대해 seed-blocked paired t-검정(독립 학습 seed n = 3)과 셀별
5-contrast family 내 Holm 보정으로 평가하며, 모든 검정은 양측 α = 0.05다.
seed 평균 클래스별 AP에 대한 Wilcoxon signed-rank 검정이 분포 무관 보조
증거를 제공한다. 평가는 세 클래스 scope(*all*, 빈도 정의 *tail*, AP 정의
*weak*)에서 보고한다.

# 4. 실험 설정

공학 응용은 지상 자연 시점과 위성 시점이라는 운용상 상이한 두 촬영 체제의
군용 항공기 탐지다 — 클래스별 데이터 수집 비용이 높고 클래스 불균형이
불가피해, 증강 예산의 배분이 실질적 엔지니어링 의사결정이 되는 환경이다.
두 벤치마크 모두 공개 데이터셋으로, 모든 결과의 재현을 뒷받침한다.

## 4.1 데이터셋

**MAD**(Military Aircraft Detection, 자연 측면/지상 시점, 공개)는 43개
기종에 걸쳐 18,832개 박스를 가진 11,788장(train/val/test
9,430/1,179/1,179)이며 학습 split 불균형 비는 10.5다. **MAR20**(Military
Aircraft Recognition 데이터셋, 위성 시점, 수평 박스, 공개)은 공식 테스트
2,511장을 제공하며 이를 최종 보고 전용으로 보존하고, 공식 학습 1,331장을
클래스 층화 80/20으로 train/val 분할한다. MAR20의 20클래스 분포는 MAD보다
뚜렷이 얕으며, 5.3절이 이를 불균형 구조의 자연 대조로 활용한다. tail
집합은 데이터셋의 속성이고, weak 집합은 각 검출기 자신의 baseline에서
유도되므로(3.2절) 셀별로 정의된다. MAD에서 두 집합은 각 13개이며 두
검출기 모두에서 서로소다. MAR20에서는 각 6개이며, 소형 검출기에서는 1개,
transformer에서는 2개 클래스가 겹친다.

## 4.2 검출기와 학습

용량이 한 자릿수 차이 나는 두 검출기를 쓴다: You-Only-Look-Once(YOLO)
계열의 소형 1-stage 검출기 YOLOv8n(3.2M 파라미터)과 Real-Time Detection
Transformer의 large 변형 RT-DETR-L(32M 파라미터). 둘 다 Common Objects in
Context(COCO) 벤치마크로 사전학습된 체크포인트에서 초기화되므로, 셀 간
차이는 용량과 아키텍처 계열이지 사전학습 코퍼스가 아니다. 둘 다 640×640,
50 epochs, early stopping(patience 15)으로 모든 arm에서 동일 스케줄로
학습하며, 배치 크기는 RT-DETR-L 8로 고정, YOLOv8n은 자동 설정이고 나머지
하이퍼파라미터는 프레임워크 기본값이다. 모든 arm-셀 조합은 독립 seed 3개로
학습하고, 통계는 3.6절대로 seed에 걸쳐 집계한다.

## 4.3 셀과 예산

표 1이 4개 데이터셋 × 검출기 셀을 요약한다. YOLOv8n 셀은 전체 2×2 요인 +
baseline을 돌리고, RT-DETR-L 셀은 축소 설계(baseline, RFS, tail-집합 2
arm)로 — 상호작용 재추정이 아니라 이득이 더 강한 검출기로 이전되는지를
검정한다. uniform arm의 pool은 데이터셋에만 의존해 검출기 셀 간에
공유되고, weighted arm의 난이도 성분은 각 검출기 자신의 baseline 검증
AP에서 재계산되므로 그 배분은 검출기별이다. 예산은 데이터셋 크기에
비례한다: MAD *B* = 1,000 (*K* = 13, 클래스당 5–200), MAR20 *B* = 500
(*K* = 6, 5–100). 실현 예산은 모든 셀에서 계획 예산과 같다(검증 실패율:
MAD 시도의 ≤ 21%, MAR20 0.6% — 3.4절 재보충 메커니즘이 흡수).

**표 1.** 실험 셀. 모든 셀이 생성·검증·통계 프로토콜을 공유한다.

| 데이터셋 | 검출기 | Arms | 예산 *B* / *K* |
|---|---|---|---|
| MAD | YOLOv8n | 전체 2×2 + RFS + baselines | 1,000 / 13 |
| MAD | RT-DETR-L | 축소 (tail-집합 arm + RFS) | 1,000 / 13 |
| MAR20 | YOLOv8n | 전체 2×2 + RFS + baselines | 500 / 6 |
| MAR20 | RT-DETR-L | 축소 (tail-집합 arm + RFS) | 500 / 6 |

## 4.4 재현성

생성은 계획이 주어지면 seed-결정적이다(3.3절). 계획, 생성 로그, 검증
리포트, contrast freeze(내용 해시 포함), 클래스별 지표, 66개 주 학습 run
전체 — 및 5.4절의 object-gate 재학습 — 의 가중치가 보관되며, 데이터셋
정규화부터 통계 리포트까지 전 파이프라인이 설정 파일만으로 수동 개입 없이
실행된다. 코드와 산출물은 게재 시 공개한다.
